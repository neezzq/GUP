# Game Updater

Windows-утилита для обслуживания игровых компьютеров и центральный сервер для клубных аккаунтов.
Загрузку, проверку и запись игровых файлов выполняют установленные официальные клиенты.

**Статус 0.1.0.** Сервер, панель, API и обработка очереди покрыты автоматическими тестами.
Адаптеры используют наблюдаемые признаки обновления и останавливаются при неоднозначном интерфейсе.
Перед эксплуатацией требуется прогнать реальные обновления на Windows для каждой используемой платформы.
Автоматический вход зависит от доступности проверяемой формы UI Automation в конкретной версии клиента.

## Сервер на Debian 12/13 или Ubuntu

Понадобятся Docker Engine с Compose v2, DNS-имя с публичным сертификатом и доступ Caddy к портам 80 и 443.
Направьте DNS-запись на сервер. В файле `server/.env` задайте `GUP_DOMAIN`, например `updates.club.example`.
FastAPI доступен Caddy по закрытой сети Docker. Если подсеть `172.29.55.0/24` уже используется,
выберите свободную и согласуйте адрес Caddy в Compose с `--forwarded-allow-ips` в Dockerfile.

Из корня репозитория выполните:

```bash
cd server
cp .env.example .env
# Укажите свой домен в .env
docker compose build backend
docker compose images backend
```

Подготовьте файл ключей. Замените `IMAGE` именем или ID образа backend из предыдущего вывода.

```bash
install -d -m 0700 secrets
IMAGE='имя-или-ID-образа-backend'
docker run --rm --user 0:0 --network none \
  --mount "type=bind,src=$PWD/secrets,dst=/keys" "$IMAGE" \
  sh -ec 'python -m server.manage --keys /keys/keys.json init-keys && chown 10001:10001 /keys/keys.json'
docker compose up -d --build
docker compose exec backend python -m server.manage admin operator
docker compose ps
curl --fail --silent "https://updates.club.example/api/v1/health"
```

Команда `admin` запрашивает пароль интерактивно. При её повторном запуске пароль или имя действующего
администратора заменяются, и текущие административные сессии завершаются. Используйте пароль
длиной от 14 символов. SQLite хранится в томе `gup_data`, а файл ключей с правами `0600`
подключается к backend отдельно как Docker Secret. Для rootless Docker назначайте владельца
файла внутри того же пространства UID, что использует Compose.

При корпоративном TLS-прокси сборка принимает доверенный CA через BuildKit secret `pypi_ca`.
Например, `docker build --secret id=pypi_ca,src=/path/to/trusted-ca-bundle.pem -t gup-backend:local .`.
Чтобы Compose использовал этот образ, задайте `image: gup-backend:local` для backend в локальном
override и запускайте его с `--no-build`.

### Панель и подключение

1. Откройте `https://<домен>/admin/accounts`, войдите и сохраните разрешённые к использованию клубные аккаунты.
2. Во вкладке **Компьютеры** создайте отдельный ключ для каждого компьютера. Выберите, к каким аккаунтам ему разрешён доступ. Через 10 минут или после использования ключ становится недействительным.
3. На Windows запустите `GameUpdater.exe` в отдельной защищённой учётной записи обслуживания. Введите адрес, имя компьютера и полученный ключ. Токен сохраняется в Windows Credential Manager.
4. При запуске клиент проверяет сервер и обрабатывает выбранные лаунчеры последовательно. Проблемы входа и подтверждения отображаются в окне и, при наличии связи, в журнале сервера.
5. Для переподключения с новым токеном отзовите старую запись, создайте новый одноразовый ключ и нажмите **Переподключить**. Активные клиенты прекращают серверные операции после отзыва.

Посетители должны использовать отдельную учётную запись Windows без доступа к рабочему столу
обслуживания. Уже авторизованная локальная сессия может использоваться при сетевой недоступности
сервера. При явном отказе сервера в авторизации обработка останавливается.
Отзыв токена закрывает доступ к серверу и не отменяет уже переданные учётные данные или локальную
сессию игрового клиента. Утилита проверяет интерактивный рабочий стол, другие пользовательские
сеансы, процессы в обнаруженных каталогах игр и минимум 1 ГиБ свободного места на соответствующих
дисках. Точный необходимый объём зависит от игры и официального клиента.

### Свой аккаунт без передачи пароля Game Updater

В панели **Аккаунты** кнопка **Войти через …** открывает официальный сайт сервиса в
отдельной вкладке. Для обновления игр войди в официальный лаунчер Windows на каждом
компьютере. Если нужно указать способ входа в Game Updater, раскрой **Настроить вход
для обновлений на ПК** и сохрани имя или ник. Для Epic Games можно отметить **Через Steam**,
если этот способ предлагает сам Epic. Активную сессию сохраняет лаунчер на компьютере.

Если на сервере уже есть пароль этого лаунчера, переключение предложит явно удалить
его. После переключения сервер перестанет выдавать данные для входа этому лаунчеру.
При запросе Steam Guard подтверди вход в Steam или на телефоне. Если Steam только
привязан к Epic и вход через Steam отсутствует, используй доступный способ входа в Epic.

В Windows оставь включёнными нужные лаунчеры и параметр **Начинать проверку при
открытии**. Game Updater запускает их по одному в заданном порядке. Для каждого
используется распознанная сессия. Если нужен вход или подтверждение, сделай это в
официальном окне и нажми **Проверить повторно**.

Game Updater восстанавливает свёрнутое окно запущенного лаунчера. Если видно только значок
в трее, приложение повторно вызывает официальный EXE. Если очередь пропустила запуск,
строка лаунчера показывает причину, например другую сессию Windows, работающую игру
или ошибку запуска.

### Резервная копия и восстановление

Создайте согласованную копию SQLite через SQLite Backup API. Сохраните дамп и копию текущего
`secrets/keys.json` раздельно, в защищённых хранилищах. Команды выполняются из `server/`.

```bash
umask 077
docker compose exec -T backend sh -ec '
  scratch=$(mktemp -d)
  trap "rm -rf $scratch" EXIT
  python -m server.manage backup "$scratch/backup.sqlite3"
  cat "$scratch/backup.sqlite3"
' > gup-backup.sqlite3
```

Перед восстановлением сохраните текущую БД, остановите backend, выберите копию и соответствующие
ключи. Команда проверяет целостность SQLite и возможность расшифровать аккаунты, затем заменяет
файл БД. Существующие подключения, lease и административные сессии в копии аннулируются. После
восстановления компьютеры подключаются заново.

```bash
docker compose stop caddy backend
docker compose run --rm --no-deps -T backend sh -ec '
  umask 077
  cat > /tmp/restore.sqlite3
  python -m server.manage restore /tmp/restore.sqlite3
' < gup-backup.sqlite3
docker compose up -d
```

При наличии файлов `-wal` или `-shm` проверьте, что другие процессы закрыли базу, и выполните
контрольную точку SQLite перед повтором восстановления. Сохраните эти файлы вместе с базой
до контрольной точки.

### Ротация ключа шифрования

Сначала сделайте резервную копию. Запустите ротацию при остановленном backend. Команда `new-key`
добавляет новый активный ключ в отдельный файл, а `reencrypt` переводит аккаунты на него одной
транзакцией. Старые ключи нужны для резервных копий, созданных до ротации.

```bash
docker compose stop caddy backend
IMAGE='имя-или-ID-образа-backend'
docker run --rm --user 0:0 --network none \
  --mount "type=bind,src=$PWD/secrets,dst=/keys" "$IMAGE" \
  sh -ec 'python -m server.manage --keys /keys/keys.json new-key && chown 10001:10001 /keys/keys.json'
docker compose run --rm --no-deps backend python -m server.manage reencrypt
docker compose up -d --force-recreate
```

## Windows x64

Для сборки на Windows 10/11 установите Python 3.12 x64 и выполните `client\build.bat`.
Скрипт создаёт окружение, устанавливает зависимости, запускает тесты и собирает
`dist\GameUpdater.exe` и `dist\GameUpdater.exe.sha256`. Для запуска собранного EXE Python отдельно
не требуется. При каждом пуше в `main` GitHub Actions собирает EXE, проверяет запуск и
публикует предварительный релиз с файлами EXE и SHA-256. Номер запуска различает
сборки одной версии клиента. [Скачать сборки](https://github.com/neezzq/GUP/releases)

События клиента хранятся в `%LOCALAPPDATA%\GameUpdater\events.log`. При нажатии **Приостановить**
новые действия ожидают продолжения, а официальному клиенту разрешено закончить своё скачивание.
**Остановить** прерывает наблюдение, а текущая операция официального клиента может продолжаться.
Приложение пытается закрыть только запущенный им процесс с подтверждённым состоянием очереди.

### Обновление Game Updater

Вверху окна отображаются версия и номер сборки. При запуске приложение ищет установленные
клиенты по реестру, стандартным папкам и запущенным процессам. Поиск работает до подключения
к серверу. В настройках виден найденный путь, а для нестандартной установки можно указать
его вручную.

Нажми **Обновить приложение** после завершения очереди игр. Game Updater проверит релизы
`neezzq/GUP`, скачает более новую сборку, сверит SHA-256, заменит EXE и перезапустится.
Настройки и подключение хранятся отдельно. Нужны доступ к GitHub и право записи в папку с EXE.
Для перехода на эту версию со сборки без кнопки скачай её один раз со страницы релизов.

## Проверка и ограничения адаптеров

| Клиент | Источники обнаружения и состояния | Проверка реального обновления в Windows |
|---|---|---|
| Steam | Реестр, `libraryfolders.vdf`, ACF, экран загрузок и UI Automation | Ожидается |
| Epic Games Store | Локальные `.item`-манифесты и UI Automation | Ожидается |
| Riot Client | `RiotClientInstalls.json`, сведения установки Windows и UI Automation | Ожидается |
| Battle.net | Сведения установленных продуктов Windows и UI Automation | Ожидается |
| VK Play | Сведения установленных продуктов Windows и UI Automation | Ожидается |
| EA App | Сведения установленных продуктов Windows и UI Automation | Ожидается |
| Lesta Game Center | Сведения установленных продуктов Windows и UI Automation | Ожидается |

На реальном стенде проверьте RU и EN, сохранённую сессию, запрошенный вход и 2FA, обнаружение
запущенной игры и настоящий цикл скачивания, распаковки и установки. Steam-логи, журналы
Battle.net Agent и проприетарные манифесты VK Play и Lesta пока не включены в проверку состояния.
Список программ Windows может не содержать часть игр. Если клиент не предоставляет
однозначных элементов UI Automation, утилита фиксирует неподтверждённый результат. Проценты
отображаются только при наличии числителя и знаменателя от клиента. Для входа приложение
использует ввод через UI Automation в проверенном окне. Внешние браузеры и формы без проверяемого
контекста переходят в режим ручного входа. CAPTCHA, 2FA и запросы перезагрузки остаются под
контролем администратора.

Тесты без Windows запускаются командой `python -m pytest -q` после
`python -m pip install -r requirements-dev.txt`. Воспроизводимые сценарии очереди используют
тестовые адаптеры и записи манифестов. Они не подтверждают фактическое обновление игр.
Для проверки создания окна запустите `GameUpdater.exe --smoke-test`.
На Windows флаг `--verify-uia` дополнительно проверяет запуск UI Automation.

При сборке этой версии прошли 23 теста на Linux и 23 теста под Windows Python в Wine.
Через Docker Compose и Caddy проверены HTTPS, вход администратора, настройка аккаунта,
регистрация устройства, lease, отзыв доступа и целостность резервной копии SQLite.
Windows x64 EXE собран PyInstaller и прошёл проверку создания окна в Wine.
Wine предоставляет собственную библиотеку UI Automation. Для проверки штатного UIA
и полного цикла обновления нужен Windows 10/11 с установленными официальными клиентами.

Реализация читает форматы VDF и Epic, описанные в исходниках ValvePython и Legendary,
и использует структуру сведений об установке Battle.net, описанную в Playnite Extensions.
Лицензии перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

- [ValvePython/vdf](https://github.com/ValvePython/vdf)
- [Legendary](https://github.com/derrod/legendary)
- [Playnite Extensions](https://github.com/JosefNemec/PlayniteExtensions)
- [pywinauto](https://github.com/pywinauto/pywinauto)
- [CustomTkinter](https://github.com/TomSchimansky/CustomTkinter)
